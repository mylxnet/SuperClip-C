| 5 | `.bat` 报 `'dp0"' 不是内部或外部命令` 一类碎片错误 | `cmd.exe` 在 cp936 下把 UTF-8 中文的 lead byte 与**下一个字符**配成一对 | 所有 `.bat`/`.ps1` 内容改纯 ASCII，中文只留在 `.md` 与 C++ 源里 | 编码问题会吃掉标点，报错点离病因很远 |

| 8 | `IDWriteTextFormat::Clone` 编译不过 | 它要求 `_WIN32_WINNT ≥ 0x0603`，项目基线是 Win7（`0x0601`） | 右对齐格式改为向工厂再要一份 | Win7 基线会砍掉一批"看起来人人都有"的 API |
| 9 | 首跑 CMake 报 `Manually-specified variables were not used: CMAKE_C_COMPILER` | `project()` 只声明 CXX | 脚本不再传该变量 | 交叉工具链参数要按项目实际语言传 |

## 5. 架构决策的"为什么"（只记代码读不出来的）

- **帮助窗的接力页只存在过 v2.4.0 一版，v2.4.1 已按用户决议删除**：v2.4.0 曾把 C15 接力写成一页
  「填表接力」插在第 4 位（理由：接力是快速模式的手势延伸，紧接「两种粘贴模式」最顺），代价是其后各页
  页码整体后移一位。**v2.4.1 用户决议直接删掉该页**（原话见 `CHANGELOG.md` v2.4.1 段），帮助回到 9 步、
  「置顶」回到第 9 步。教训与现状：**帮助页讲的是"用户要按什么"，不是"程序里有什么"**——接力功能仍在
  代码里（`RelayService`、`Alt+左键`、`` Alt+` `` 兜底键），但对用户的主路径（呼出→选→贴）是旁支，
  用户不希望它在引导里占一页。所以**引用帮助页码时优先写页面标题**（如"「复制模式」那一步"），
  少用裸序号——本页与 README、DESIGN、TESTING 都按这个口径改过一轮。
- **本轮 Release 附件用 mingw 交叉件，而不是等 MSVC 链**：用户要的是"push 代码和产物、项目收官"，
  而本机没有 MSVC/SDK，`PackageRelease.bat` 第一步就跑不了。两条路：交一个**来源与边界都写在 README 醒目块里**的
  mingw 件（超 3 MB 门这件事在 README/CHANGELOG/§6 三处挂着账），或者不交产物只交代码。用户裁定前者。
  理由：这份件的构建链、单测、实机走查证据齐全，缺的只是"MSVC 也这么编"这一条旁证；把它藏起来不交，
  反而让"收官"停在一个无法复现的口头状态。

- **点选才算绑定、空格才粘贴**：防误触；单击只做选中，避免鼠标一碰就把内容怼进别人窗口。
- **收藏只在【收藏】视图显示、且不参与「清除」**（C10/C12）：用户裁定收藏要永久保存；数组的
  `[收藏区 | 非收藏区]` 分区不变式**原样保留**，改的只是 `RebuildDisplay()` 的过滤条件——
  持久化顺序、`Boundary()` 插入位、`MoveToBack` 沉底、FR-04 末位淘汰都依赖这个不变式。
- **来源标注不上屏、只参与搜索**（C11）：列表要干净，但按进程名搜得到。
- **启动即置顶**（C13；实现上要绕开"非前台时系统丢带"，见 §4 坑 #12）；**监听窗口禁 message-only**（否则丢 `TaskbarCreated` 广播）；**键入模拟用 `SendInput`**。
- **零网络是硬红线**（AC-8）：连"文件对话框"都不引 `comdlg32`；`dwmapi`/`shcore` 走 `LoadLibraryW` 动态加载，不入链。
- **署名可点 = AC-8 的边界，不是豁免**（v2.1.0）：单击 `by Mr lin` 只做 `ShellExecuteW("open", 常量 URL)`，
  本进程零套接字零 HTTP 栈，联网动作发生在系统选定的外部浏览器里——与用户自己双击一个 `.url` 同构。
  这条写在 `doc/DESIGN.md` §1.2 的边界裁决里，含最严解读下应回退为静态署名的说明。**规范 HTML 原文未改**（改动契约原文需单独授权）。
- **自研极简 JSON**：原 ADR 选 RapidJSON，落地时环境离线取不到包，改为约 180 行的对象数组解析器；
  副产品是第三方审计面归零。决策记录在 `src/core/Json.h` 头注释。
- **C15「填表接力」为什么是 Alt+左键、为什么"不绑进程"**（v2.2.0，方案讨论收敛过程代码里读不出来）：
  ① 用户原始需求是"绑到 Excel/浏览器进程上，点输入框就贴第一行"，但**刚点中的框所在窗口本身就是前台窗**，
  绑定这条伪需求去掉后，接力天然支持跨程序（前半程 Excel、后半程浏览器），也不与靶心绑定互相干扰；
  ② 修饰键**不能用 `Ctrl`**：注入本身就是 `Ctrl+V`（`PasteService.cpp` 还要防"用户按着 Ctrl"补发 Ctrl up），
  且 `Ctrl+左键` 在 Excel 会**加选成多重区域导致粘贴直接报错**、在浏览器是**开新标签**；`Shift+左键` 在 Excel
  是扩展选区，也排除。`Alt` 的风险只有 `Alt+Ctrl+V` = Excel 选择性粘贴对话框，对称地在注入前用
  `GetAsyncKeyState(VK_MENU)` 判断并补发 Alt up 化解。**注意 Alt 必须用 `GetAsyncKeyState` 而不是 `GetKeyState`**：
  接力是在钩子 `PostMessage` 来的 `WM_APP` 处理里注入的，`GetKeyState` 读的是上一条已处理按键的状态，不可信；
  ③ 侧键（`WM_XBUTTONDOWN`）**注册不了全局热键**（`RegisterHotKey` 只吃键盘），且不是人人有鼠标，故只作备选；
  ④ **推进语义复用现有机制**：每次取"实时列表第一行"（`Store::RelayNext()`），贴过靠 C8 的 `MoveToBack` 沉底、
  C14 的第一行自然上位，**不新增队列指针**，逻辑层只剩两个可单测的纯函数；⑤ 与点选**语义相反**：
  `ProcessPicker` 的钩子 `return 1` 吞掉点击（不能改动用户选区），接力必须 `return 0` **放行**，
  否则目标输入框拿不到光标、粘贴没有落点——这两个钩子绝不能互相"借鉴"返回值。
- **C15 为什么在 v2.3.0 把"开关"整个删掉**（2026-10-05 用户否决 v2.2.0 交互模型，原话"相当于把快速粘贴里的空格
  变成 ALT+鼠标左键，也不用剪贴板界面隐藏"）：① **开关本身是误触发的根源**——右键菜单武装、武装即 `HideForRelay()`
  藏窗、`RelayArmable()` 要求停在【全部】视图且搜索框为空，四道门槛叠加的结果是"用户按 Alt 点了半天、钩子根本没装"，
  而这正是他反馈的"功能没实现"；② 作用域改用**已有状态**裁决（快速模式 + 主窗在屏），不新增第三个开关态，
  也就不存在"忘了关"——闲置 5 min 定时器（`kRelayIdleMs`/`ID_RELAY_IDLE`）与 `Touch()` 一并删除；
  ③ 取条口径从"必须是全局第一条"改成**所见即所贴**（`display_.front()`，过滤/搜索态按屏幕第一行算），
  与 C14「快速模式空格贴第一行」完全对齐，两条路径共用同一个 `RelayNext()`；
  ④ 贴完（第一行是灰条）**不再自动卸钩**，只提示一句——用户随时复制一条新的，第一条就又是新的那条，
  卸钩反而要求他重新武装，回到 ① 的老坑；⑤ 代价是钩子常驻时间变长（只要列表开着就挂着），
  所以 `SyncRelayHook()` 必须是**幂等重装**而不是"只装一次"：低层钩子被系统按 `LowLevelHooksTimeout`
  静默摘掉后没有任何查询 API，症状只是"Alt+点不灵且不报错"，每次状态确认都重挂才能自愈。
- **C15 兜底键为什么是 `` Alt+` `` 而不是用户最初要的 `Alt+空格`**（v2.3.3，用户原话「能否修改组合键CTRL+ALT+空格键，ALT+空格键？？」）：
  `RegisterHotKey(MOD_ALT, VK_SPACE)` **能注册成功**（Windows 只保护 `Win+L` 与 `Ctrl+Alt+Del`），但它会把
  `Alt+空格`＝「打开窗口系统菜单（还原/移动/大小/最小化/最大化/关闭）」**从所有程序手里静默抢走**——资源管理器、
  命令行、各种对话框、以及习惯 `Alt+空格` 再按 `N`/`X` 关窗的人全部受影响，而 SuperClip 不给任何提示，
  用户只会觉得"这键怎么失灵了"。`Ctrl+空格` 更糟：那是中文输入法的中/英切换键。这与项目既有口径一致
  （`Shift+F10` 当初就是因为"后果不可见即不可测"而没做，只放行 `VK_APPS`）。`` Alt+` `` 与呼出键 `` Ctrl+` ``
  **同键位、只差修饰键**，肌肉记忆不用重学，且不撞任何系统或输入法快捷键。给用户的三档里他选了这一档。
- **UI 层不做条件编译打桩**：无头环境跑不了 D2D/剪贴板/托盘，这部分只能实机走查，跑不了就标**未验证**。

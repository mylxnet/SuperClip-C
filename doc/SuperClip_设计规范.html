SuperClip 超级剪贴板

完整设计规范（Design Specification）· 可直接交付 AI / 开发者从零实现

文档版本 v1.2 平台 Windows 10 / 11 (x64) 形态 桌面应用 · 单文件 exe 状态 已冻结需求（v1.1 含 §4.4 顺序勘误 C7；v1.2 含收藏显示与清除语义勘误 C10/C12）
一句话目标： 一个后台常驻的 Windows 剪贴板增强工具，自动记录复制过的纯文本内容，支持 Excel 表格拆分、搜索、收藏、双粘贴模式，托盘常驻、全局快捷键呼出，最终打包成不依赖 .NET 运行时的单文件 exe 分发。

3. 数据模型

单条剪贴板记录：

ClipItem {
  string   Id           // 唯一标识（GUID），init-only
  string   Content      // 文本内容，init-only
  ClipType Type         // Text | TableCell，init-only
  int?     SourceRow    // 表格单元格行号（1 起），普通文本为 null
  int?     SourceCol    // 表格单元格列号（1 起）
  DateTime Timestamp    // 复制时间，init-only
  string   Hash         // 内容 SHA-256（小写十六进制），用于去重，init-only
  bool     IsFavorite   // ★/☆，可变，需通知 UI
  bool     IsPasted     // 已粘贴（灰显），可变，需通知 UI
  string   SourceLabel  // 只读计算属性："来自表格：第 X 行 第 Y 列" 或 ""
}
IsFavorite / IsPasted 变化须实时反映到 UI，应使用支持属性变更通知的实现（如 ObservableObject + [ObservableProperty]，或手写 INotifyPropertyChanged）。

4. 核心算法规范

4.1 去重（FR-02）

hash = SHA256(content).ToLowerHex()
if Items.Any(i => i.Hash == hash):
    remove that item           // 先移除旧副本
item = new ClipItem { ..., Hash = hash, IsFavorite = oldItem?.IsFavorite ?? false }
insert item at front of non-favorite region   // 保证收藏始终置顶

4.2 TSV 表格拆分（FR-05）

IsTable(text):  return text.Contains('\t')

Parse(text):
  normalized = text.Replace("\r\n","\n").Replace('\r','\n').Trim('\n')
  rows = normalized.Split('\n')
  for r in 0..rows.Length-1:
    cols = rows[r].Split('\t')
    for c in 0..cols.Length-1:
      if string.IsNullOrEmpty(cols[c]): continue   // 跳过空单元格
      emit Cell { Content=cols[c], Row=r+1, Col=c+1 }
行/列均从 1 计数。空单元格跳过（避免垃圾记录；如需保留空单元格可去掉该判断）。纯文本（不含 \t）作为单条 Type=Text 记录，不做拆分。

4.3 排序与置顶（FR-03/FR-08/FR-10）

  • 显示顺序由单一有序集合（如 ObservableCollection<ClipItem>）维护。
  • 收藏置顶：排序时所有 IsFavorite==true 的项排在前，普通项排在后；各自保持相对顺序。此处的「置顶」指集合存储顺序（末位淘汰、沉底、插入位都以此为依据），不等于上屏可见——可见性见本节末勘误（v1.2，C10）。
  • 顺序不变式：集合结构为 [收藏区 | 非收藏区]；两个区内部均「最新在前」——即非收藏区最前 = 最新，非收藏区末尾 = 最旧。
  • 新复制项插入到「第一个非收藏项之前」（即非收藏区最前 = 最新位置）。
  • 快速粘贴沉底：粘贴后将该项从集合移除并 Add 到末尾（非收藏区末尾 = 最旧位置），其相对顺序被持久化保留。
  • 切换收藏时重排一次（收藏前 / 普通后）；各区相对顺序不变（稳定重排，如 stable_partition）。
勘误（v1.2，C10）：FR-08 原文写作「收藏项置顶分组显示」，与本节「集合结构为 [收藏区 | 非收藏区]」相互牵连：若收藏项真的显示在列表前部，则任何普通视图都会以收藏区开头，序号、分组分隔线与「最新在前」的阅读预期都要为此成立；而 FR-07 又单独提供了「收藏」这一过滤视图。二者按字面无法同时满足。经用户决议（2026-10-04）统一为：收藏项只在【收藏】过滤视图显示，「全部 / 文本 / 表格单元格」一律剔除收藏项，分组分隔线随之取消。本节定义的存储顺序不变式、插入位、末位淘汰、快速粘贴沉底全部不变，改动只落在「显示过滤」这一层。代价（已确认接受）：点星后条目立刻离开当前视图，故状态栏需给出 3 秒去向提示。

4.4 自动清理（FR-04）

while (nonFavoriteCount > 500):
    oldest = Items.Last(i => !i.IsFavorite)    // 非收藏区末尾 = 最旧（见 §4.3 顺序不变式）
    Items.Remove(oldest)

收藏项永不参与清理。

勘误（v1.1，C7）：本节原伪码写作 Items.First(i => !i.IsFavorite) 并注释「非收藏区最前 = 最旧」，与 §4.3「新复制项插入非收藏区最前、最新在上」及 FR-04「自动删除最旧的」相互矛盾——按原字面实现会淘汰最新条目。现统一为：末位淘汰（Last(!IsFavorite)）。三处佐证：FR-04 需求原文（删最旧）、§4.3 插入位（最新在前）、FR-10 快速粘贴「沉底」（用过的排到末尾并最先被清理）。同理，while 循环每轮只可能移除末尾项，可优化为一次批量删除超额尾部区间。
勘误（v1.2，C12）：本节的「清理」专指 FR-04 的自动上限淘汰，而原规范对手动「清除」（FR-13）却写作「清空所有记录（含收藏）」——同一份文档里，收藏在自动路径上「永不参与清理」，在手动路径上却被一键抹掉，语义相反。经用户决议（2026-10-04）统一为：收藏永久保存，「清除」只清非收藏区；删除某条收藏的唯一路径是先取消收藏使其回到非收藏区。原 FR-13 的「清空所有记录（含收藏）」与 §12 ADR 中「用户确认选项 B」一并作废，替换见 §12。

4.5 搜索防抖（FR-06）

OnSearchTextChanged(value):
    searchTimer.Stop(); searchTimer.Start()   // 300ms 定时器，到期才 RefreshDisplay()

RefreshDisplay():
    q = Items
    q = apply FilterType (All/Text/TableCell/Favorite)
    if kw != "": q = q.Where(i => i.Content.Contains(kw, IGNORE_CASE)
                               || i.SourceLabel.Contains(kw, IGNORE_CASE))
    DisplayItems = new ObservableCollection(q)   // 列表绑定 DisplayItems

6. 系统集成（Win32）

6.1 剪贴板监听

  • 使用 AddClipboardFormatListener(hwnd) + 处理窗口消息 WM_CLIPBOARDUPDATE = 0x031D。
  • 监听挂在主窗口的 HwndSource 上；窗口 Hide()（非关闭）时句柄仍存在、消息循环继续，故收起后仍持续监听。
  • 读取用 Clipboard.GetText()，需 try/catch（剪贴板可能被其他进程锁定）。

6.2 全局热键

RegisterHotKey(hwnd, id=1, MOD_CONTROL, VK_OEM_3)   // VK_OEM_3 = 0xC0 即 ` ~ 键
// 收到 WM_HOTKEY = 0x0312 → ToggleVisibility()：Visible 则 Hide，否则 Show+Activate

6.3 模拟键入（FR-11）

PasteText(text, targetHwnd):
  Clipboard.SetText(text)                       // 会触发 WM_CLIPBOARDUPDATE（由调用方屏蔽）
  if targetHwnd != Zero:
     selfHwnd = Process.MainWindowHandle
     AttachThreadInput(targetThread, selfThread, true)   // 提升 SetForegroundWindow 成功率
     SetForegroundWindow(targetHwnd)
     AttachThreadInput(targetThread, selfThread, false)
  keybd_event(CTRL,0,0); keybd_event(V,0,0);
  keybd_event(V,0,KEYUP); keybd_event(CTRL,0,KEYUP)      // 发送 Ctrl+V 到目标光标处

屏蔽自监听（关键）

写入剪贴板会再次触发 WM_CLIPBOARDUPDATE，必须忽略，否则会把"刚粘贴的内容"又记成新历史：

bool _internalPaste = false;
Timer _guard(400ms) → on tick: _internalPaste = false;   // 兜底

DoPaste(item, moveToEnd):
  _internalPaste = true
  PasteService.PasteText(item.Content, lastExternalWindow)
  ViewModel.PasteDone(item, moveToEnd)
  _guard.Restart()

WndProc(WM_CLIPBOARDUPDATE):
  if _internalPaste: _internalPaste = false; return;     // 忽略自身写入
  text = ReadClipboardText(); if text: AddFromClipboard(text)

捕获目标窗口

「目标窗口」= 用户粘贴前最后活跃的外部窗口。在主窗口 Deactivated 事件中记录 lastExternalWindow = GetForegroundWindow()。用户按 Ctrl+` 呼出主窗口时，主窗口获得焦点、外部窗口 Deactivated → 正好记下了目标窗口句柄。

6.4 系统托盘

  • NotifyIcon（WinForms），双击图标 = 打开窗口；右键菜单 = 「打开 / 退出」。
  • 退出时 notifyIcon.Dispose() 并注销监听/热键，再 Application.Shutdown()。

复位语义仅快速模式：恢复最初（按时间）顺序 + 清除所有灰显用户定义：回到最初复制的数据模式
排序持久化按当前显示顺序序列化，重启保留（含沉底）验收标准 3
开机自启不做用户明确不要
分发形态自包含单文件 win-x64分发给他人各 Windows 环境，免装 Runtime
空单元格拆分时跳过完全为空的单元格避免无意义垃圾记录
自动清理方向（C7）末位淘汰：删除非收藏区末尾项v1.1 勘误。原 §4.4 伪码取 First(!IsFavorite) 与 FR-04「删最旧」及 §4.3「最新在前」冲突，按字面会误删最新条目；以需求原文与沉底语义为准
收藏可见性（C10）收藏项只在【收藏】过滤视图显示，「全部 / 文本 / 表格单元格」剔除收藏v1.2 勘误。原 FR-08「置顶分组显示」与 §4.3「集合结构 [收藏区 | 非收藏区]」、FR-07 另设「收藏」视图相互冲突（普通视图无法既按最新在前又不被收藏区打头）。存储顺序不变式、插入位、末位淘汰、沉底全部保留，改动只落在显示过滤层；分组分隔线取消，点星后条目立刻离开当前视图 → 状态栏给 3 秒去向提示

13. 边界条件与风险

  • 风险 SetForegroundWindow 被拒：目标窗口为管理员权限或全屏时可能失败 → 已用 AttachThreadInput 缓解，失败则静默（粘贴可能落到错误窗口）。
  • 风险 剪贴板被锁：读取/写入时其他进程占用 → 全程 try/catch 兜底。
  • 边界 复制图片/文件：仅记录纯文本，非文本内容忽略。
  • 边界 完全相同的连续复制：去重只保留一条（更新时间戳）。
  • 边界 搜索时焦点在搜索框按空格：输入空格而非触发粘贴。
  • 禁区 严禁引入任何 HTTP/网络库或远程调用（AC-8）。
